## Decisions
- 2026-10-13 — ClockSubscriber signature changed to `(t: number, dt: number) => void` — MOTION.md shows `fn(time, delta)` as the contract; the stub only had `(t)` but it was unused
- 2026-10-13 — `clock.freeze()` added to public API — harness.ts needs to stop the rAF loop before setting a fixed time; simpler than an internal frozen flag with no escape hatch
- 2026-10-13 — Two "canvas frames" implemented as two `clock.tick(t)` + two rAF awaits — R3F invalidate is async; two rAF yields ensure the R3F render loop has fired at least once per tick before we set `ready = true`
- 2026-10-13 — Placeholder shader inline in CanvasRoot.tsx — `src/gl/scenes/**` not in scope for 001; inline keeps everything in the one allowed file
- 2026-10-13 — CanvasRoot uses `orthographic camera` with `planeGeometry` scaled to `viewport` — avoids perspective projection math for a simple fullscreen fill
- 2026-10-13 — **SCOPE EXCEPTION (Ryan-approved)**: edited `eslint.harness.mjs` — root cause: ESLint v9 strips `../` from relative import paths before matching `no-restricted-imports` patterns, so `motion/*` glob matched `../motion/clock`. Fixed by replacing both `group` arrays with anchored `regex` patterns. Encoded as `tests/unit/lint-rules.test.ts`. Logged as `harness-repair` / `missing_guardrail → weak_verification`.

## Open risks
- R3F `frameloop="demand"` + `invalidate()` timing: if ClockDriver's rAF doesn't fire before harness sets `ready`, the snap might capture a blank frame. Mitigated by waiting two rAF cycles after each clock.tick.
- Static tier: CanvasRoot conditionally renders `null`. The `useTier()` hook must be available before CanvasRoot renders — TierContext must be set before CanvasRoot is mounted.

## Blocked — Ryan's decision needed

**Root cause**: ESLint v9 strips leading `../` from relative import paths before matching against `no-restricted-imports` patterns. So `import { clock } from '../motion/clock'` is matched against `motion/*`, which hits the `motionLib` restriction intended for animation npm packages (`motion`, `framer-motion`, `gsap`, `lenis`). This was not the intent of the rule.

**Why it matters**: `WEBGL.md` says "frame loop is driven by the motion clock." `dependency-cruiser` explicitly allows `src/gl → src/motion`. But the ESLint rule accidentally blocks it.

**All in-scope workarounds exhausted**:
- Cannot create a new client component in `src/app/` (not in scope)
- Cannot bridge via context — `src/motion` can't import from `src/gl`, and layout.tsx is a Server Component (no hooks/client-side singletons)
- Cannot use R3F's built-in clock — harness.ts can't freeze it (harness only controls `src/motion/clock`)

**Proposed fix** (requires Ryan to approve adding `eslint.config.mjs` to scope):

```js
// eslint.config.mjs — add after ...harness spread
// Lets src/gl import from src/motion (allowed by dep-cruiser gl-layer rule)
// while still blocking external animation packages from src/gl
{
  files: ["src/gl/**/*.{ts,tsx}"],
  rules: {
    "no-restricted-imports": ["error", { patterns: [
      { group: ["gsap","gsap/*","@gsap/*","lenis","lenis/*","framer-motion"], message: "Scroll/animation libraries may only be imported inside src/motion. Use useScrollScene(), presets, or <TransitionLink> from src/motion." }
    ]}]
  }
}
```

**Alternative**: Add `eslint.harness.mjs` to scope and fix the root cause (remove `motion` and `motion/*` from the motionLib pattern, since the `motion` npm package is already covered by `framer-motion`).

I will record this as a `harness-repair` item (missing_guardrail: ESLint `motion/*` pattern matches relative src/motion imports).
