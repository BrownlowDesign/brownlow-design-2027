## Approach

1. **GLSL loader** — `src/gl/glsl-loader.mjs` (webpack + turbopack) resolves `#include` at bundle time; `next.config.ts` wires both; TypeScript declarations in `src/gl/glsl.d.ts`. `pnpm shaders` already resolves includes in Node.js independently.
2. **Scene registry** — `src/gl/registry.ts`: `register(id, cleanup) → unregister`. CanvasRoot holds no scene state; scenes self-register.
3. **Update CanvasRoot** — add `<View.Port />` (drei), remove PlaceholderQuad. Clock/ProgressDriver stay.
4. **Reference scene** — `src/gl/scenes/_reference/`: `ref.vert` + `ref.frag` use `#include "tokens.glsl"`, uniforms uTime/uProgress/uTransition/uResolution. `Scene.tsx` wraps in a `<View track={ref}>`. Static tier shows `poster.png`.
5. **Routes** — `/lab/canvas` (two Views: reference scene × 2, different scroll progress feeds) + `/lab/canvas/next` (same reference scene, uTransition=1 state) for cross-route persistence test.
6. **Tests + snaps** — harness snaps at progress 0/.5/1, tp 0/.5/1; memory test across 20 navigations.
7. **ADR-0004** — document View tracking approach, registry design, static-tier poster pattern.

## Decisions

- 2026-10-14 — Use `src/gl/glsl-loader.mjs` (ESM webpack loader) rather than a third-party package. No new dependency needed; avoids turbopack compatibility unknowns.
- 2026-10-14 — drei `<View track={ref}>` + `<View.Port />` for scene placement. No tunnel needed since CanvasRoot and scenes share the same React tree (root layout contains Canvas; route components are children).
- 2026-10-14 — Registry stores only `id → cleanup` pairs. No global scene state in registry; CanvasRoot subscribes to registry events to trigger re-render.

## Open risks

- Turbopack may not support ESM `import.meta.url` in custom loaders. If `this.resourcePath` is unavailable, fall back to CJS loader syntax.
- drei `View.Port` API may have changed in v10. Will verify import before building Scene.tsx.
