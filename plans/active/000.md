### Escalation: token collision in denied files

**Root cause.** Both `tokens/base/color.json` and `tokens/semantic.json` define `"color": { "$type": "color", … }` at the top level. Style Dictionary v4 (with `log.warnings: 'error'`) treats any duplicate path — even with the same value — as a fatal collision.

**Why I can't fix it.** `tokens/**` is in the task's deny list. The two files that need touching are `tokens/semantic.json` and/or `tokens/build.mjs`.

**Proposed fix (pick one — simplest first):**
1. **Remove `"$type": "color"` from the top-level `color` group in `tokens/semantic.json`.** The type is already declared in `base/color.json`; semantic tokens inherit it. One-line change, no behaviour difference.
2. **Change `warnings: 'error'` → `warnings: 'warn'` in `tokens/build.mjs`.** The collision is value-identical (both say `"color"`) so it's harmless; treating it as warn lets the build proceed while still surfacing real collisions.
