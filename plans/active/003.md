## Decisions

- **2026-10-15**: `useScrollScene()` built in this task per Ryan's direction (case-study page is key).
- **2026-10-15**: `MotionPageTransition` motion.div needs `position: relative` — without it, the non-positioned element sits below the canvas (z-index: 0 fixed) and is invisible. ViewTransition (A) and GsapOverlay's wrapper div (C) both happened to promote their content above the canvas; the Motion wrapper needed an explicit fix.
- **2026-10-15**: Variant B harness detection uses `useSyncExternalStore` (server snapshot: false, client snapshot: from window.location.search) — the only approach that avoids both the lint rule (`setState` in effect) and hydration mismatches.

## Open risks
- Variant A (ViewTransition) — browser support note says "Chromium 125+, recent Safari, Firefox; some animations may behave differently in Safari." Portfolio is iOS-heavy; need to verify morph works on Safari before recommending.
- Canvas continuity is the hardest constraint. Every variant must keep the `<Canvas>` mounted across navigation — Next.js App Router's default unmounts the entire subtree on route change. All three variants need to anchor the canvas in a persistent layout layer above the route slot.
- `useScrollScene()` is in scope — wraps `gsap.context()` so all triggers revert atomically on unmount. Must live in `src/motion/` (not per-variant); case-study page imports it.
